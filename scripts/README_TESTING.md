# Тестовый контур (test contour)

Рабочий процесс: **разработка на dev (порт 8001) → гейт → перенос на live (порт 8000) → проверка → выключить за собой.**
Live-сервер (8000) — это «реальная программа», его не трогаем во время разработки.

## Скрипты (PowerShell, из корня проекта)

| Скрипт | Что делает |
|---|---|
| `scripts\dev_server.ps1` | DEV-сервер на **8001** с авто-перезагрузкой. Тут ведём разработку. |
| `scripts\check.ps1` | **ГЕЙТ**: `pytest` + in-process smoke-тест всех эндпоинтов. GREEN = можно катить в live. |
| `scripts\serve_live.ps1` | Перенос на **LIVE 8000** (перезапуск прод-сервера). Только после GREEN. |
| `scripts\stop_all.ps1` | Выключить оба сервера (8000 и 8001) — «за собой». |
| `scripts\smoke_test.py` | Сам smoke-тест (вызывается из `check.ps1`; можно и отдельно). |

## Порядок работы

```powershell
# 1. поднять dev-контур (отдельное окно)
scripts\dev_server.ps1            # http://127.0.0.1:8001, авто-reload

# 2. ... правим код, проверяем на 8001 ...

# 3. гейт перед переносом
scripts\check.ps1                 # должно быть GREEN

# 4. перенос на реальный + проверка
scripts\serve_live.ps1            # http://127.0.0.1:8000

# 5. выключить за собой
scripts\stop_all.ps1
```

Smoke-тест поднимает настоящее FastAPI-приложение и дёргает все эндпоинты
(`/api/meta`, `/api/optimize`, `/api/plan-empire`, America/Lincoln и др.) —
ловит runtime-ошибки, которые юнит-тесты не видят (битый payload, 500 в ручке,
сломанный реестр, неверный cwd).
